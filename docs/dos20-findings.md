# DOS 2.0: the display audit (November 2026, begun)

*DOSHO.EXE, 2.0.1 (English) and the German 2.0 build; the same game as Windows 3.1 and Mac 2.0.1 (`docs/dos-findings.md`).*

- **Programs** (private repo: `extracted/dos-2.0.1`, `extracted/dos-2.0-German`; `decompiled/dos-2.0.1`, `dos-2.0-German`): every DOSHO.EXE on the archive.org disks and in the `Spaceward_Ho_1992.zip` install tree is the one English build (md5 5d230351...).
  The German one (17 Feb 1993, 523,840 bytes) is not PKLITE-packed. Its HOMONO.PRS and HOCOLOR.PRS came out round-sized (the disk image is probably one disk of a set).
- **Decompile.** PKLITE unpacked by emulation (`tools/decompile/dos-unpack.py`, unicorn); the Borland VROOMM overlays (49) relocated and loaded at segments 0x9000 up, their INT 3Fh stubs patched to far jumps
  (`dos-flat.py`; the stub-header format is written in `decompiled/dos-2.0.1/HOW.md`); Ghidra real mode with DS set (`DosHo.java`); 1,965 (English) and 1,976 (German) routines. The segment numbers are the ones this repo already quotes
  (`FUN_9000_0cd5`).
- **Table:** `docs/display/dos20.json` (`node tools/display-audit.js dos20`): one row for every English routine: 1,535 internal (no string, no video or BIOS access, no call of a drawing routine), **430 open** display candidates, each
  with why. The German build is the same code with its own words (not tabled separately). The program has no named API, so a routine that draws only through a library routine two calls deep is not told apart; that limit is in each internal row.
- **Skin:** the `dos` skin (`js/skins/dos`), OS look `dos`; none of the 430 has been compared yet.

## The screens (compared against the running original, November 2026)

The DOS program runs in DOSBox (the install tree's `HO!.CFG`, `SOUNDRV.COM` beside the extracted files; the English build, keyboard driven through X11 test events). Screenshots are in the scratch folder of the session (`v20dos-orig-*.png`, `v20dos-remake-*.png`); the program's windows are the Windows 3.1 dialog templates of `docs/win20-findings.md` drawn by its own window library (title bar, bold monospace text, red hot-key letters, 3-D buttons).

- **Frame:** a 640x480 screen: title bar "Spaceward Ho! - jake in MilkyWay in 2000", menu bar `File  Options  Ships  Galaxy  Window` (no Help), left column of three panels (planet numbers and the three-bar chart; fleet list box with "Stationed at: ..." / Fuel, Speed, Scrap; money lines and the budget bars; Tech Spending chart), the map on the right with an "End Turn Ctrl+T" button. The dos skin shows the classic page: a card panel, the map, its own menu names. **Not rebuilt** (gap): this whole frame and the panels' layouts.
- **Menus (fixed here):** File: About Ho!..., New Game..., Open Game..., Save Game [Ctrl+S], Revert To Saved, Close [Ctrl+W], End Turn [Ctrl+T], End Turn & Switch Players [\], Exit. Options: Force Turn Update, Auto Play..., I'll Update Turns, Set Polling Time..., Set Battle Speed..., Show Event Messages, Review Announced Battles, Give Overspending Warnings, Sound (the last four checked with a diamond). Ships: List Ship Types..., Create New Ship Type..., List All Fleets..., Organize Ships..., Build Ships at <star>..., Scrap Current Fleet, No Battles here.... Galaxy: Compare Players..., List All Explored Stars..., Send Message..., Zoom In, Zoom Out, Fix Spending. Window: Tech Spending, Reports. The dos skin lays its commands out in that order (`menuLayout` in `js/skins/dos/ui.js`, key texts "[Ctrl+S]" through `T.keyName` in the classic skin); commands the remake lacks show dimmed as the original's do when idle (Save Game, Revert To Saved, I'll Update Turns, Set Polling Time: a browser saves every change and has no network polling), the remake's own commands follow at the end of the last menu. Kept differences: "…" for "...", Set Battle Speed… opens the remake's Preferences, Create New Ship Type… opens the Build window (which holds the designer), Exit and Close both go to the title, the check diamond is the classic check, Tech Spending is not a menu item (the panel is always shown), the review-battle and organize words are the classic ones.
- **Windows seen, all unbuilt (gaps):** About (picture, "Licensed to:" lines, OK), Startup (Open Game / New Game / Cancel over the title picture), New Game file window (Filename, Directory, Files, Directories: a kept difference), Create New Galaxy (picture buttons for density, style, size, computer intelligence, a "Number of Computer Players" slider, Cancel / Create; the remake's New Game is a long form), Player Entry, New Player Registration (Skill Level, Sex, Join), Ship Types (list, picture, Rename, OK, Scrap This Type), New Ship Type (Name, Range/Speed/Weapons/Shields/Mini sliders, Class list, costs, Name It For Me / Cancel / OK), List of All Fleets, Shipbuilding queue, List of All Explored Stars (name, temperature, gravity, metal, owner), Battle Speed (with "Fully Animated Battles"), Auto Play (three radio buttons and a seconds slider), Compare Players ("Sorry, no comparisons until the year 2010." with Show Skills).
- **The 129 gap rows of the first table** were read again: 68 are settled (run-time, loaders, sound driver, resource files, file prompts, hot-seat texts, the fleet block, the planet panel, the Game Info sentence, the "--more--" pager); **61 are not settled**: routines of the program's own window library and game windows (9000-c000 overlays, the 5,158-line a000:328b, a000:c80c, 9000:76c0, b000:87fb ...) that were not traced to their window. The method that worked: `refs.json`-style scan of the code bytes for the data-segment offsets of the literal strings (846 strings in DS 0x4ea9) and for the ids of the 585 HO.PRS strings in the decompile; the Ghidra labels in the table's first notes (Version 14, Player money, WARNING ...) are unreliable names of data the code indexes. A trace with a disassembly (none is saved) would settle the rest. `node tools/display-audit.js dos20` passes (a gap does not fail it, by its own rules).
- **German:** the German build's menu and dialog words are HO.PRS's; the skin's own menu words in German come from `js/ui-text.js` (the Amiga's and DOS 2.0's German where those rows name them, ours otherwise); checked by `tools/ui-lang-audit.js dos` (en, fr, de, tr, es).
